# `/delegate`

[English](delegate.md)

把一件支线活交给另一个智能体，等它把答案带回这里。这个对话照常往下走；另一个智能体在自己的会话里干活，你可以打开看、跟着读，或者插手。

```text
/delegate  查清楚 transcript 那个测试为什么时好时坏
/delegate codex gpt-5.5 high  看看还有没有地方在读旧的配置格式
/delegate @parser-cleanup  空文件的情况也处理一下
```

**MCP：** 支持。智能体可以用 `delegate` 工具自己做同样的事，另一个智能体用 `report_back` 回答。见[下文](#mcp)。

## 适合用来

- 能和手头这件并行的活：追一个时好时坏的测试、去代码别处查点东西、并行试另一种做法。
- 用另一家模型的长处：让 Codex 去深挖某个问题，Claude 接着往下干，反过来也行。
- 接着找以前交过活的那个智能体——用 `@` 选它，它上次了解到的东西都还在。

## 怎么运作

1. **你这边的智能体先写交代。** 另一个智能体看不到这个对话，所以你敲的内容其实是在告诉*你这边的*智能体要交出去什么。它根据自己知道的，写一份对方单独拿到也看得懂的交代。
2. **另一个智能体在自己的会话里干活。** 新开的会出现在侧边栏里；如果你用 `@` 选了已有会话，交代就发给那个会话。
3. **答案送回这里。** 另一个智能体干完后，答案会送到这个对话，由你这边的智能体接着处理。如果它干完了却没交答案，Sealwire 会提醒它一次，然后把它最后一条回复转过来。

你这边的智能体不用停下来等：对方干活的时候它可以继续干自己的。

## 拿它来审

`/delegate` 也能用来请人审：

```text
/delegate claude  review 这一轮
```

一句就够：交代是你这边的智能体写的，它会把这一轮改了什么、为什么改都写给对方。下一轮用 `@` 选同一个审阅方，它记得自己上次提过什么。

和 [`/review`](review.zh-CN.md) 不同，交活出去的智能体不是只读的，能改文件。只想要它的意见，就加一句"别改文件"。

## 选项

- **provider、模型、思考强度**——交给谁。默认换一家 provider，因为第二个模型比同一个模型再来一份更有价值。
- **`@`**——交给一个已经开着的会话，而不是新开一个。
- 指示必须写。一个从零开始的智能体猜不到你要什么。

## 限制

- 新开的智能体拿到的权限永远不会比这个会话大。如果用 `@` 选的会话权限比这个会话大，会被拒绝。
- 一个会话最多能请来 5 个别的智能体。
- 用 `@` 选的会话如果正在忙、在等批准、在等这个会话给它答案，或者属于某个任务、Orchestrator 或审阅，会被拒绝。

## MCP

每个普通会话都有 Sealwire 的 MCP 工具，所以交活和交答案两头都不用你动手：

| 工具 | 谁用 | 做什么 |
|---|---|---|
| `delegate` | 要找帮手的智能体 | 找一个新的智能体干一件事，或者给它以前找过的智能体再发一件 |
| `report_back` | 干活的智能体 | 把答案交回给找它的那一方 |

智能体自己调用 `delegate` 时，和你敲 `/delegate` 有几处不同：

- 它需要 **Full access (YOLO)**。权限受限的会话会被拒绝，并被告知改为建议你敲 `/delegate`。
- 它写的消息直接就是交代，没有单独写交代那一步。
- 新开智能体时它必须指定模型（或者要默认的）。如果它选的是旗舰模型，要等你批准才会开始。

`report_back` 每个普通会话都有，权限受限的也有：它只是回答找它的那一方，不会让它做到超出对方权限的事。

所有 provider——Claude Code、Codex、Cursor、OpenCode、Pi——都有这两个工具，哪一家都可以在任何一头。唯一的例外是 Pi：它总是以 Full access 运行，所以只有 Full access 的会话才能把它请来。

## 和另外几条比

- [`/handover`](handover.zh-CN.md) 也会请来另一个智能体，但什么都不会回来：另一个智能体把活接过去。用 `/delegate` 的话，这边的智能体仍然主事，并且拿到答案。
- [`/review`](review.zh-CN.md) 请另一个智能体来*看和判断*。交活出去的智能体是来*干活*的，能改文件。
