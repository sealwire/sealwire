# `/handover`

[English](handover.md)

当前的智能体写清楚事情做到哪了，另一个智能体从那里把整件事接过去。这是单向的：新的智能体自己往下干，什么都不会回到这个对话。

```text
/handover
/handover codex gpt-5.5 high  重点写清楚解析器还剩哪些没做
/handover @release-prep  还差更新日志没写
```

**MCP：** 不支持。没有交接工具——把整件事交出去永远由你决定。接手的智能体也不会被要求回报。

## 适合用来

- 某一家的配额用完了，想换一家把活干完。
- 对话太长、历史堆得太多，换个只带交接说明的新会话，思路更清楚。
- 想从这里开始换一个模型接手。

## 怎么运作

1. **这边的智能体写交接说明。** 它总是用同一组标题，免得漏掉要紧的东西：目标、当前状态、已完成的工作、剩下的工作（包括下一步具体做什么）、关键决定和约束、改过的文件、测试，以及阻碍和风险。命令后面你写的话，会决定它在哪些地方写得更细。
2. **新的智能体拿到交接说明**，并被告知这件活现在归它了：从下一步接着干，不清楚的地方自己拿主意。
3. **两个会话各走各的。** 原来的会话保持原样，新会话的任何东西都不会回到它这里。

## 选项

- **provider、模型、思考强度**——谁来接手。默认还是同一家 provider，因为是同一件事接着干。要换就写另一家。
- **`@`**——交给一个已经开着的会话，而不是新开一个。
- 命令后面的话可写可不写。只敲 `/handover`，就是写一份完整的交接说明，不额外指定重点。

## 限制

- 智能体必须是空闲的：正在跑一轮的时候不能交接。
- 新的智能体在同一个项目里干活，拿到的权限永远不会比这个会话大。Pi 总是以 Full access 运行，所以只有 Full access 的会话才能交接给它。
- 用 `@` 选的会话必须能接活，规则和 [`/delegate`](delegate.zh-CN.md#限制) 一样。
- 交给同一个智能体的交接，同一时间只能有一个在路上。

## 和另外几条比

- [`/delegate`](delegate.zh-CN.md) 是找另一个智能体帮忙：它干其中一块，答案回到这里，这边的智能体仍然主事。`/handover` 是交出去：从此由另一个智能体负责。
- [`/goal`](goal.zh-CN.md) 让当前的智能体一直干下去。`/handover` 是换一个智能体来干。
