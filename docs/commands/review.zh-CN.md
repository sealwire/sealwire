# `/review`

[English](review.md)

让另一个智能体检查这个对话刚做完的事。审阅方会去看你项目里真实的改动，把意见发回这里，最后给一个结论：**通过**、**需要修改**，或**拿不准**。

```text
/review
/review codex gpt-5.5 high  重点看出错时的处理
/review claude opus 5 recap  这个迁移跑两次还安全吗？
```

**MCP：** 不支持。智能体暂时不能自己发起审阅，只有你能。审阅方本身也拿不到任何 Sealwire 工具。

## 适合用来

- 提交之前，请另一家的模型把关——Codex 审 Claude 写的，Claude 审 Codex 写的。
- 只想核对某一个担心的点：provider、模型、思考强度后面写的话，会作为重点交给审阅方。

## 怎么运作

1. 先让审阅方知道做了什么。默认把你这边智能体的最后一条回复交给它。加上 `recap`，就改成先让你这边的智能体写一份工作回顾再交过去——最后一条回复没把事情说全时用这个。
2. 审阅方在自己的会话里工作，只读，和你在同一个项目里。
3. 它的意见回到这个对话，由你这边的智能体读完，决定改什么。

`/review` 只审一轮。想要多轮——智能体改，审阅方再看，直到通过或轮数用完——请点 **Request reviewer** 按钮，最多可选 10 轮。

## 选项

- **provider、模型、思考强度**——谁来审。默认换一家 provider，不用正在干活的这家。
- **`last message` 或 `recap`**——怎么让审阅方了解情况（见上）。
- **`@`**——选这个对话以前用过的审阅方，它还记得上次审了什么。思考强度和交代方式仍然可以改。

## 审阅方有多"只读"？

看 provider：

| 审阅方 | 靠什么让它改不了文件 |
|---|---|
| Codex | 真正的只读沙箱 |
| Claude Code | 收走改文件的工具，但它的 shell 仍然能写 |
| Cursor | 在 Cursor 的 plan 模式下运行 |
| OpenCode | 权限规则拒绝所有没明确允许的操作 |
| Pi | 只是叫它别改——Pi 没有受限模式 |

## 什么时候发不起来

对话要处于空闲、并且由你控制。以下情况会被拒绝：有一轮正在跑、有批准在等你、这个对话已经有一个审阅在跑、或者同一个项目里有 workflow 或任务在跑。

## 和另外几条比

- [`/delegate`](delegate.zh-CN.md) 也会用到另一个智能体，但那个智能体是来*干活*的，能改文件。审阅方只看、只下判断。
- [`/goal`](goal.zh-CN.md) 让一个智能体一直干下去，不会请另一个智能体来看。
